# Mod Feature

* [Discover code mods through KSA's mod manifest](manifest-mod-discovery.md) - StarMap reuses KSA's native manifest.toml and mod.toml discovery, reads an optional [StarMap] table from each enabled mod, and loads that mod's entry assembly, so a StarMap mod is a KSA content mod plus a DLL
* [Discover lifecycle hooks by attribute type name](attribute-hook-discovery.md) - StarMap finds a mod's [StarMapMod] class and its hook methods by comparing attribute type names rather than Type identity, validates each signature with StarMap's own attribute instance, and invokes hooks by reflection on one shared instance
* [Frame lifecycle hooks (BeforeGui, AfterGui, AfterOnFrame)](frame-lifecycle-hooks.md) - StarMap's per-frame hooks are a prefix on Program.OnDrawUiFrame, a postfix on Program.OnDrawUiViewports and a postfix on Program.OnFrame; this maps each to its position in the KSA frame and the state that is valid there
* [Host KSA in-process from a launcher executable](host-process-launch.md) - StarMap.exe reads StarMapConfig.json, loads KSA.dll and StarMap.Core into a custom AssemblyLoadContext, fixes the working and base directories, and invokes the game's Main by reflection
* [Isolate each mod in its own AssemblyLoadContext](per-mod-assembly-load-context.md) - Every StarMap mod gets a non-collectible ModAssemblyLoadContext that resolves shared assemblies from the loader and the game first, then from declared dependency mods, then from the mod's own deps.json
* [Order mod loading with a ModDependencies graph](mod-dependency-graph.md) - StarMap parks mods whose [[StarMap.ModDependencies]] are not registered yet, releases them when the dependency loads, and retries the rest at the end, loading mods whose only missing dependencies are Optional
* [Redirect the KSA documents folder per instance](instance-path-override.md) - With -InstancePath on StarMap's command line or the STARMAP_INSTANCE_PATH environment variable, a manual Harmony prefix replaces the KSA.Constants.DocumentsFolderPath getter so settings, saves, logs, the manifest and local mods come from another folder
* [Release packaging, StarMap.API NuGet and Windows installer](release-packaging-and-installer.md) - GitHub Actions publish StarMap as a framework-dependent win-x64 folder zipped without pdb and xml files, push StarMap.API to NuGet, cut release-candidate builds from dev, and build an Inno Setup installer that writes StarMapConfig.json
* [Restart when new mods are enabled](new-mods-restart-flow.md) - A Harmony prefix on ModLibrary.PrepareAll detects mods the player just enabled in KSA's MOD FOUND popup, which StarMap skipped at launch, and offers to relaunch StarMap.exe so their code loads
* [Share contract assemblies between mods with ExportedAssemblies and ImportedAssemblies](shared-contract-assemblies.md) - A dependent mod's load context resolves selected assembly names from its dependency's load context, so both mods see one Assembly, one Type identity and one set of statics for an inter-mod contract
* [Startup lifecycle hooks (BeforeMain, ImmediateLoad, AllModsLoaded)](startup-lifecycle-hooks.md) - Where StarMapBeforeMain, StarMapImmediateLoad and StarMapAllModsLoaded fire relative to KSA's Program constructor, and exactly which game state exists at each
* [Startup modal popup with a self-pumped frame](startup-modal-popup.md) - StarMap shows its restart question during KSA's loading phase by subclassing KSA.Popup and running its own GLFW poll, ImGui frame and Vulkan submit loop, copied from the game's ConfirmMods dialog
* [Unload hook and shutdown order](unload-and-shutdown.md) - StarMapUnload runs after KSA's Main has returned and Program.Dispose has destroyed the renderer, and after StarMap has removed every Harmony patch in the process; Environment.Exit paths skip it
