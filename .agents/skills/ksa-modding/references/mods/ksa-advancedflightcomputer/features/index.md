# Mod Feature

* [6-DOF successive-convexification landing as a receding-horizon MPC on a solver thread](scvx-6dof-landing-mpc.md) - A rigid-body landing planner re-solved every cycle from the measured state with SCS on a dedicated background thread, with immutable input snapshots, a single result slot, an estimated acceleration bias, a wall-clock budget and a node ladder
* [A custom gauge button action backed by a mod enum](autostage-gauge-button.md) - Register a mod-defined enum in GaugeButtonFlightComputer.EnumTypes at immediate load, add a Button to the stock EngineControl gauge with a KittenExtensions XML patch, and give the enum toggle, lit and disabled state through Vehicle patches
* [A detachable console-window panel and world-space trajectory overlays](guidance-panel-and-overlays.md) - Draw a mod panel with the game's ConsoleStyle window skin unpinned from the main viewport, gauge-styled tab content, and click-through full-screen overlays that project CCI or body-fixed points through the main camera, all from StarMapAfterGui with fault isolation
* [Aim a transfer at a flyby periapsis instead of the body center](flyby-periapsis-targeting.md) - Retarget a stock porkchop transfer by solving Lambert to the target's center offset by the impact parameter that yields the requested periapsis, on a chosen side perpendicular to the approach, and hand the result to the stock Create button
* [Automatic staging that keeps Auto burns alive](automatic-staging.md) - A per-vehicle state machine sampled before and evaluated after the vehicle-solver apply stages on burnout, cascades through empty rows, refuses to drop the last control module, and takes back the stock out-of-propellant stop so an Auto burn survives the staging
* [Booster boostback with a drag-integrated impact predictor](boostback-impact-prediction.md) - Adopt a separated booster as its own guided vehicle, predict its impact point by integrating gravity and drag in a co-rotating atmosphere, and fly a receding-horizon boostback burn plus an engine-first glide that walks the impact onto the landing site
* [Build a KSA mod in CI from private reference assemblies](ci-reference-assemblies.md) - Strip the installed game's managed DLLs to API-only reference assemblies with Refasmer, keep them in a private bucket keyed by game build, fetch them in CI by the TestedGameVersion constant, and publish nightlies that are promoted to releases without rebuilding
* [Build vendored native libraries for Windows and Linux and check the ABI against C#](native-solver-build-and-abi-check.md) - Build Clarabel with cargo and SCS with zig cc from vendored sources with pinned, hash-verified toolchains, and compare the C# struct layouts and export list against a C probe compiled from the same headers on each target platform
* [Closed-loop MPC harness and solve-purity checks without the game](closed-loop-mpc-harness.md) - A console harness that flies the 6-DOF planner closed-loop through RK4 dynamics with injected thrust and gimbal errors to measure plan jump, path ratio and solve cost, plus determinism and threading checks that gated the worker-thread move
* [Confirm a planned flyby by propagating it through the game's patched conics](flyby-encounter-prediction.md) - Propagate a candidate burn with FlightPlan.CalculateBurnPatch and ComputeCompleteTrajectory filtered to the target, read the periapsis of the patch around the target, report a typed reason when there is none, and draw that plan in place of stock's preview
* [Convert a vehicle's state into a landing-site frame through the game's own transforms](vehicle-state-to-site-frame.md) - Build a local site frame from CCI, derive the model's body axes from the measured engine thrust direction, and convert attitude by transforming basis vectors with KSA's own quaternion so no quaternion convention is ever assumed
* [Create a stock maneuver node from a computed impulse](planner-burn-node-creation.md) - Turn an impulsive delta-v at a time into a stock Burn with Burn.Create on the right flight-plan patch and queue it through InputEvents.BurnUpdateBuffer exactly as the Transfer Planner does, so stock Auto, saves and the burn editor treat it as a normal node
* [Custom plan types in the stock Transfer Planner](transfer-planner-custom-plan-types.md) - Insert mod entries into TransferPlanner.TransferTypes and take over the window for those keys with a skip-original prefix that redraws the stock window under the same id, title and signature
* [Detect which planned burn stock just ended](stock-burn-end-detection.md) - A prefix on FlightComputer.RaisePendingAlerts captures the completed or propellant-stopped burn in Harmony state before stock clears the flags, and the postfix learns whether EndAutoBurn kept it
* [Draw several predicted orbits with a brightness ramp and custom map markers](multi-pass-preview-rendering.md) - Render one FlightPlan per planned pass through FlightPlan.AddLineInstances with per-pass dimmed orbit colors, draw apsis, node and SOI markers on the viewport's overlay draw list, and cache the expensive previews behind quantized vehicle-state keys
* [Dump the in-game solver problem as JSON and replay it offline](solver-problem-json-replay.md) - The convex-ascent request writes the exact problem it built from the live vehicle to plain SI JSON before solving, and a test-console flag re-solves that file offline with a full trace, with round-trip checks keeping old files readable
* [Entries in the stock orbit right-click menu](orbit-context-menu-shortcuts.md) - A transpiler on BurnContextMenu.Draw inserts a submenu before the popup's final EndPopup and appends entries to the "At Periapsis" and "At Apoapsis" submenus, found by reading the UTF-8 label literals from the IL
* [Feature-gated Harmony patch sets with rollback](feature-gated-patch-sets.md) - One Harmony instance per feature, validated before patching and rolled back on failure, so a game update disables one feature instead of the whole mod
* [G-FOLD fuel-optimal powered descent solved in-frame with Clarabel](gfold-powered-descent.md) - Lossless-convexification powered descent as a second-order cone program in a site-fixed frame, solved synchronously with a time limit inside the per-vehicle step and flown as committed-trajectory tracking with periodic re-solves
* [Game-free numerical assemblies with console checks against Python references](game-free-guidance-checks.md) - Keep solver and math code in separate assemblies with no game references, so console programs can check them against JAX and CVXPY reference fixtures in CI without the game, and link single game-facing files into small test executables
