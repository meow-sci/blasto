# Mod Feature

* [9P2000.L server in C#](ninep-server-in-csharp.md) - A from-scratch 9P2000.L codec, TCP server and pluggable virtual filesystem running inside the game process, which the Linux guest mounts as /sim for telemetry and as /mnt for opt-in host folders
* [Alpine guest image pipeline](alpine-guest-image.md) - A reproducible script builds a tiny Alpine Linux root filesystem with busybox init supervisors, static committed SSH keys and a manifest boot contract, smoke-boots it in QEMU, and publishes it as a pinned GitHub release that the mod build fetches
* [Build, deploy and CI](build-deploy-and-ci.md) - An MSBuild deploy target that assembles the complete mod folder on every build without deleting the player's config, NUnit suites that run game-free by default and boot a real VM when GATOS_IT=1, and GitHub workflows for testing under KVM and publishing per-OS release zips
* [Celestial body catalog reads](celestial-body-catalog-reads.md) - Reading every planet, moon and the star into a body catalog, caching the session-constant data per body so each sample only reads ECL position and velocity
* [Compile-gated game seam](compile-gated-game-seam.md) - Split the mod class into a game-free half and a Game/ half compiled only when KSA.dll is present, joined by C# partial methods that vanish when the game assemblies are absent, so CI and every library build and test without private game DLLs
* [Debug cheats for teleport, refuel, warp and impulse](debug-cheats-teleport-refuel-warp.md) - A gated /sim/debug namespace that teleports vessels to a CCI state vector, applies impulsive kicks, refills propellant and batteries, sets time warp and switches the controlled vessel, each in the frame phase that keeps it race-free
* [Embedded MQTT broker](embedded-mqtt-broker.md) - An MQTTnet broker hosted inside the game process publishes retained telemetry topics and a leaf-per-topic mirror of /sim, gated by connected clients, live subscriptions and byte changes, and turns publishes on a command topic into game-thread commands
* [External API clients and SDK](external-api-clients.md) - A typed TypeScript SDK that runs over either the /sim filesystem or HTTP, plus Rust, TypeScript and shell example programs that fly, film and decorate KSA from inside or outside the guest, demonstrating the external API surface
* [FMOD audio playback](fmod-audio-playback.md) - Play user-uploaded audio clips through KSA's own FMOD system and channel groups by creating in-memory sounds, tracking channels on the main thread, and releasing sounds only after no channel uses them, without ever touching the game's System lifecycle
* [Frame hooks with an F2-proof fallback](frame-hooks-and-f2-fallback.md) - Three StarMap hooks plus a main-viewport Harmony prefix give gatOS one game-thread work slot per frame that keeps running when the player hides the HUD
* [FX editors via reflection](fx-editor-reflection.md) - Expose the game's built-in engine-plume, plume-trail, cloud and terrain debug editors as live-editable data by reflecting into private renderer fields, replaying each editor's own apply sequence, and recording pristine values so every change can be reset
* [Game-thread command queue](game-thread-command-queue.md) - Every external write (file, HTTP, MQTT, MCP, serial) becomes an immutable command that a transport thread enqueues and awaits while the game thread drains, routes and executes it with errno-style results
* [Ground-clutter texture override](clutter-texture-override.md) - Replace a stock ground-clutter texture at runtime by decoding a user image with the game's own loaders and re-pointing its existing bindless texture slot, with the stock view captured for restore and old images retired only after every frame in flight has finished
* [Host-guest transport over slirp TCP](slirp-tcp-host-guest-transport.md) - Every channel between the game process and the guest is plain TCP over QEMU user-mode networking, with host ports advertised on the kernel command line, because virtio-9p, virtiofs and vsock have no host backend on Windows QEMU
* [HTTP /v1 API server](http-v1-api-server.md) - A dependency-free HTTP/1.1 server on a raw TcpListener inside the game process that serves JSON snapshots, Server-Sent Events, a long-poll sim-time wait, an OpenAPI document, a per-leaf mirror of /sim and one generic command endpoint
* [Ignition, staging and module actuators](ignition-staging-and-module-actuators.md) - Ignite, shut down, stage, toggle engines and RCS, fire decouplers, undock and drive part animations by calling the same entry points as KSA's own keybinds, most of which queue into the game's input buffers
* [IVA cabin physics in an own Bepu world](iva-cabin-physics-bepu.md) - Make loose cabin props float, slam aft under thrust and fling under rotation by simulating them in a separate BepuPhysics Simulation in the vessel's assembly frame, driven by the vessel's accelerometer and body rates and written back onto IVA SubPart transforms
* [KSA anchor churn tracking](ksa-anchor-churn-tracking.md) - Every method that touches a KSA member carries a documentary KsaAnchor attribute with the member, source file, verification date, game version and churn risk, backed by runtime health latches and a scope catalog plus an upgrade playbook that turn a new game build into a bounded work list
* [Logging shim and perf stats](logging-and-perfstats.md) - A game-free logging interface that every library uses, swapped at load for a sink on KSA's Brutal LogCategory, plus allocation-free single-writer timing and allocation counters shown live in the mod's status window
* [Manual throttle and RCS inputs](manual-throttle-and-rcs-inputs.md) - Setting manual throttle and RCS translate/rotate commands by reflecting into the private Vehicle._manualControlInputs struct, the same field KSA's keyboard handlers write and the solver copies each step
* [MCP server for AI agents](mcp-server-for-agents.md) - A stateless Streamable HTTP Model Context Protocol endpoint inside the game process, built on the official C# SDK with a hand-rolled HTTP adapter, that groups the simulation into logical JSON resources and control tools for AI agents
* [ModMenu entry with a fallback menu](modmenu-entry-with-fallback-menu.md) - Draw the same mod menu through ModMenu's ModMenuEntry attribute when ModMenu is installed and through a Harmony postfix on KSA's empty Program.DrawProgramMenusHook when it is not, plus a status window and a confirmation modal that never block on background work
* [Part and module state reads](part-module-state-reads.md) - Reading engines, tanks, solid motors, batteries, power, RCS, solar panels, docking ports, decouplers, animations and the part tree through KSA's vehicle-wide module lists and struct-of-arrays state lists
* [Part light cone control](light-cone-control.md) - Switch part lights and change their brightness, colour and spotlight inner and outer cone angles at runtime by cloning each light's shared template per instance, with the engine facts from the repo's analysis of how KSA renders spotlights
* [Particle bursts from the emitter pool](face-particle-bursts.md) - Spawn one-shot particle effects anchored to a vessel or an EVA kitten's face by taking an emitter from KSA's shared pool and initializing it with a ParticleEmitterReference built entirely in C#, plus the engine facts from the repo's particle-system analysis
* [Per-vessel scale and force-render cheats](scale-and-force-render-cheats.md) - Rescale a whole vessel by writing Part.Scale recursively, keep a vessel drawn at any distance by prefix-replacing KSA's sub-pixel cull, and show IVA interiors from outside by flipping the internal-template flag, each with Harmony patches installed only while in use
* [Programmable camera director](programmable-camera-director.md) - Take ownership of KSA's main camera by installing a FixedController subclass through a reflected protected setter, parking the viewport in Fixed mode, and composing each frame's pose from tracks, overrides and a captured baseline inside the engine's own viewport pass
* [Projected sticker decals](sticker-projected-decals.md) - Spray user images onto vessels, terrain and ground clutter as screen-space projected decals drawn after KSA resolves its offscreen target, reconstructing scene positions from the reverse-Z depth buffer in shaders compiled at runtime against the game's own GLSL includes
* [purrTTY custom shell contract](purrtty-custom-shell-contract.md) - gatOS plugs a new shell type into another mod's terminal by importing that mod's exported contract assembly through an optional StarMap mod dependency, sharing one registry instance, while still loading cleanly when the other mod is absent
* [qcow2 overlay guest disks](qcow2-overlay-guest-disks.md) - Keep a pristine shipped base image read-only and store all guest changes in a per-profile qcow2 overlay in the user data folder, with version-pinned boots, grow-only resize, a PID lock file and a one-click reset
* [QEMU microVM as a game child process](qemu-microvm-host-process.md) - Boot, supervise and shut down a QEMU Linux VM from inside a KSA mod with an async state machine, per-OS accelerator ladders with TCG fallback, an SSH readiness probe and a QGA-QMP-kill shutdown ladder, all off the main thread
* [Screen stream frame capture](screen-stream-frame-capture.md) - Capture the game's rendered scene without stalling by transpiling a hook into Program.RenderGame just before its command buffer ends, blitting the offscreen image into a small per-frame-slot staging buffer read back frames later, and streaming it as Kitty terminal graphics
* [Serial bus with CCSDS, NMEA and SCPI](serial-bus-ccsds-nmea-scpi.md) - A virtual serial port into the guest, backed by a QEMU virtio-serial chardev socket, streams active-vessel telemetry as NDJSON, NMEA-0183 sentences or CCSDS space packets and accepts SCPI-style command lines that answer OK or ERR with an errno
* [Snapshot-diff flight events](snapshot-diff-flight-events.md) - KSA has no public event bus for flight events, so gatOS derives situation, SOI, engine, flameout, docking, decoupling, animation and battery events by diffing consecutive immutable snapshots
* [Solver-phase drain for flight computer setpoints](solver-phase-command-drain.md) - A Priority.First Harmony prefix on Universe.ExecuteNextVehicleSolvers is the one window where flight computer modes, burns, refills and teleports written from the main thread survive KSA's async vehicle solver
* [SSH shell sessions into the guest](ssh-shell-session-into-guest.md) - Each purrTTY terminal tab is an SSH.NET PTY channel into the guest over a loopback port forward, with lazy VM boot on first open, host-key pinning, a non-blocking input writer thread and thread-agnostic output events
* [Synthetic camera follow anchor](synthetic-camera-follow-anchor.md) - Implement KSA's IFollowable on a mod-owned object that re-resolves a vessel, part, body or fixed point on every call, so the stock camera follows it and every camera pose stays an offset measured in the engine's own frame pass
* [Telemetry sampler and snapshot store](telemetry-sampler-snapshot.md) - A rate-limited game-thread sampler reads every vehicle and body into one immutable snapshot and publishes it with a single volatile swap that any number of transport threads read without locks
* [The /sim file models](sim-filesystem-file-models.md) - How a synthetic 9p filesystem must behave so ordinary Unix tools work on live game data, covering snapshot-memoized sensor files, growing-log streams, blocking event and alarm files, and writable control files that return real errno values
* [Timed command scheduler](timed-command-scheduler.md) - A game-free scheduler that plays back scripts of millisecond-offset commands on render, wall or sim-time clocks, ticked on the game thread immediately before the command drain so a command due this frame executes this frame
* [TOML config seeded from a shipped template](toml-config-seeded-template.md) - Ship an editable gatos.default.toml in the mod folder, copy it once to a live gatos.toml in the user data folder, deserialize with Tomlyn into one typed class, clamp bad values with a warning instead of failing, and persist in-game changes atomically on a background task
* [Vehicle and EVA paint](vehicle-and-eva-paint.md) - Recolour vessel parts by injecting GLSL into KSA's part fragment shader at compile time and packing colours into spare per-instance state bits, and recolour EVA kittens by binding gatOS-owned material clones, both opt-in and fully reversible
* [Vessel flight-state reads](vessel-flight-state-reads.md) - How gatOS reads position, velocity, attitude, altitude, mass, orbit, navball, environment and encounters from KSA.Vehicle each sample, in which coordinate frames, and how it scrubs KSA's sentinels
* [Welds that pin one vessel to another](welds-vessel-anchoring.md) - Rigidly attach a source vessel to a target vessel or one of its parts by re-teleporting the source onto the anchor pose every frame after the vehicle solver has finished
* [World-space textured quad (thug_life)](thug-life-world-space-quad.md) - Draw a custom textured quad attached to a vessel part into KSA's offscreen scene pass by postfixing SuperMeshRenderSystem.RenderMainPass with a lazily created Vulkan pipeline built against the engine's own render target
