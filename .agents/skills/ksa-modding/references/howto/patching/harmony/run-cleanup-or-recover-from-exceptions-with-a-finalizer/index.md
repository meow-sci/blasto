# How-To

* [Mark the asker in a Priority.First prefix, clear it in a Priority.Last finalizer](run-cleanup-or-recover-from-exceptions-with-a-finalizer-7.md) - Answer one shared terrain height query differently for the vehicle being prepared and for the camera by marking the asker in a Priority.First prefix on Vehicle.PrepareWorker and clearing it in a Priority.Last finalizer, and lend a value across TeleportToLocation the same way
* [Prefix with __state and a finalizer that restores an edited input](run-cleanup-or-recover-from-exceptions-with-a-finalizer-3.md) - Inject a navigation target into the by-ref struct passed to FlightComputer.ComputeControl on the solver thread for exactly one call, record that in __state, and put the struct back in a finalizer
* [Prefix, postfix and finalizer as a transaction around loads](run-cleanup-or-recover-from-exceptions-with-a-finalizer-4.md) - Wrap UncompressedSave.Load, Universe.DeserializeSave and Universe.LoadSystem in prefixes that defer and open a transaction, postfixes that restore, and finalizers that close it and turn a silent native read failure into a reported exception
* [Restore what a prefix changed around one game call](run-cleanup-or-recover-from-exceptions-with-a-finalizer-1.md) - A prefix removes collidable shapes (or reveals interior part templates) for the length of one game call and hands the originals to a finalizer through __state, so the state is put back even when the call throws
* [Swallow an exception and finish the method's remaining work](run-cleanup-or-recover-from-exceptions-with-a-finalizer-2.md) - Replay the tail of TransferPlanner.SetTransferInfo from a Harmony finalizer after a NaN Period makes the stock method throw, and swallow the exception by returning null
* [Thread-static construction context scoping a transpiler and a prefix](run-cleanup-or-recover-from-exceptions-with-a-finalizer-6.md) - Pebbles redirects the ground clutter renderer's material buffer lookups to a private buffer and swaps a fragment shader variant only while a ThreadStatic construction context is active, with a finalizer that leaves the context on every path
* [ThreadStatic override set in try/finally around the mod's own submission](run-cleanup-or-recover-from-exceptions-with-a-finalizer-5.md) - Make a prefix on the shared VolumetricExhaustRenderer.AddInstance edit a plume only while the mod itself is submitting it, using a ThreadStatic scope that the mod's call site opens and closes in try/finally
