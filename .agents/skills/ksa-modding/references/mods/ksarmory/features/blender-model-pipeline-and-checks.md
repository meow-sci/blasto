KSArmory ships eleven GLB mesh atlases. Three of its parts (the Pantsir launcher, the LAU-7 rail
and the EO director) are not modelled by hand at all: `tools/model/pantsir.py` builds them out of
primitives in headless Blender, `palette.py` writes a flat-swatch texture atlas, and `build.sh`
runs both, exports `src/KSArmory/Meshes/KSArmory_MeshAtlas.glb` and installs it.[^ksarmory-model-readme]
Every other atlas is authored in a live Blender session over MCP and committed as an export; its
`.blend` is not in the repository.[^ksarmory-blender-skill]

The reusable part is the **checking**. Z-fighting and degenerate UVs look identical in game
(flickering white speckle), neither shows in a Blender preview render, and a mesh-name mismatch
loads a part with a body missing and nothing in any log. So the repo carries pure-Python readers
of the GLB binary that find each of these without Blender or the game, and runs them from the
model build, the pre-push script, CI and the deploy script.[^ksarmory-checkmesh][^ksarmory-check-all]

## How it works

### Generation (three parts only)

| Step | What it does |
|---|---|
| `palette.py` | Writes `KSArmory_{Diffuse,PBR,Normal}.png`: a 4x4 grid of 128 px flat swatches in a 512 px atlas, plus `palette.json` with each swatch's UV centre. PBR is R = ambient occlusion, G = roughness, B = metalness[^ksarmory-palette] |
| `pantsir.py` primitives | `box()`, `cyl()`, `cone()`, `fin()`, `sphere()` each name a swatch; `_finish` applies the transform, reuses the existing `UVMap` layer and box-projects every face into a small patch around that swatch's centre (`project_to_swatch`)[^ksarmory-pantsir] |
| `box()` inflation | Every box grows by `SKIN` (6 mm) plus a per-box, per-axis jitter of up to `JITTER` (10 mm) from one seeded `random.Random(0x9A5D)`, so abutting faces interpenetrate instead of sharing a plane[^ksarmory-pantsir] |
| `join_group` | Merges each assembly into one named mesh; turret, pods, radar, guns and optic head are recentred on their pivots because a subpart rotates about its own mesh origin, and the XML puts the offset back with `<Position>`[^ksarmory-pantsir] |
| `export` | Names each body `KSArmory_Subpart_*` plus a `_VM` copy, then exports GLB with `export_yup=False` so Blender's axes are part space (+X up and boresight, +Y forward, +Z right)[^ksarmory-pantsir][^ksarmory-model-readme] |
| `report_muzzles` | Prints the tube table to paste into `KSArmory/Weapons.xml` and writes `muzzles.json` (tube positions, pivots, reference elevations, gun muzzles, optic mount)[^ksarmory-pantsir][^ksarmory-muzzles] |
| `build.sh` | Runs Blender (a Windows binary driven from WSL through `wslpath -w`), copies `muzzles.json` back, installs the atlas, prints bounds with `meshinfo.py`, then runs `checkmesh.py`; `--previews` and `--pose` render without touching the committed atlas[^ksarmory-model-build] |

### Offline checks

| Tool | Catches | How |
|---|---|---|
| `checkmesh.py` | Coplanar overlapping faces and near-parallel faces 0.3 to 4 mm apart | Every triangle reduced to a sign-canonical plane, quantised at 2e-4, bucketed; overlap area measured in 2D, reported above 2.5e-3 m^2[^ksarmory-checkmesh] |
| `checkmesh.py` | Zero-UV-area triangles | `degenerate_uvs` computes each triangle's UV area; zero area means a zero tangent and NaN shading[^ksarmory-checkmesh] |
| `checkmesh.py` | Node whose mesh is not named after it | `unpaired_names`: Blender silently renames a mesh to `X.001` when an orphan holds `X`[^ksarmory-checkmesh] |
| `checkmesh.py --compare` | "Did my edit change anything?" | Order-independent surface fingerprint, because the exporter permutes the index buffer on every rebuild[^ksarmory-checkmesh][^ksarmory-model-claude] |
| `checkswept.py` | Pieces adrift, covers standing proud, assemblies passing through each other anywhere in their travel | Rebuilds any pose from the pivot-local atlas plus `muzzles.json` and tests convex primitives with SAT[^ksarmory-checkswept] |
| `validate-parts.py` | Unresolved SubPart, Material and Mesh Ids; missing or case-mismatched files; XML not listed in `mod.toml`; Ids declared twice (counting atlas meshes); launch and optic geometry disagreeing with `muzzles.json`; planes shared between two subparts as the XML places them; unsized stacking connectors | One script over the asset XML, `Sim/Arsenal.cs` and the GLBs; `--offline` skips the checks that need KSA's Core content[^ksarmory-validate-parts] |

`validate-parts.py` runs in `deploy.sh` (offline), `check-all.sh` and both CI workflows;
`checkmesh.py`, `palette.py --check`, `checkring.py --check` and `checkswept.py` run in
`check-all.sh`.[^ksarmory-deploy][^ksarmory-check-all]

### What the engine actually reads from a GLB

`MeshAtlasFileReference.DoLoad` opens the file with `GltfLoader` and registers one `MeshReference`
per glTF mesh, with `Id = GltfJson.Meshes[i].Name`; if `ModLibrary.Register` refuses the Id
(already taken) it reuses the existing registration instead of the new mesh
(MeshAtlasFileReference.cs L26-L45).[^ksa-meshatlasfilereference][^ksa-modlibrary] So the
`<Mesh Id>` in the asset XML must equal the glTF mesh name, and a SubPart declared under a mesh's
name is a collision the loader resolves silently, which is why the mod keeps
`KSArmory_<name>_SubPart` apart from the atlas's `KSArmory_Subpart_<name>`.[^ksarmory-assets-xml]
Core's own subparts declare the `_VM` twin under `<MeshView>` beside the `<PartModel>` mesh
(CoreFuelTankAAssets.xml L11-L19), and the mod copies that shape.[^ksa-core-fueltank-assets][^ksarmory-assets-xml]

## Lifecycle and timing

All of this runs at build time, outside the game. The game-side moment it protects is
`startup:asset-load`: `ModLibrary.LoadAll` calls each mod's `LoadAssetBundles` and then runs every
queued loader in parallel (`Parallel.ForEachAsync` over `Loaders`, ModLibrary.cs L478-L522), which
is where the atlas's meshes are registered by name.[^ksa-modlibrary][^ksa-meshatlasfilereference]
Only XML files listed in `mod.toml`'s `assets` reach that point.[^ksarmory-mod-toml]
A wrong mesh name or a missing file is not an exception there; it is a reference that resolves to
nothing later, which is the reason for checking before the game ever starts.[^ksarmory-validate-parts]

```python
# tools/model/pantsir.py L207-L312
# Every box is grown by this much on each side so abutting parts interpenetrate instead of
# sharing a face plane, plus a per-box, per-axis jitter of up to JITTER on top. See box().
SKIN = 0.006
JITTER = 0.010

# Deterministic, so the mesh is reproducible and diffable. Seeded once here rather than per
# call so that adding a primitive reshuffles nothing before it.
_jitter = random.Random(0x9A5D)
# ...
def box(size, loc, rot=(0.0, 0.0, 0.0), swatch="hull"):
    # ...
    bpy.ops.mesh.primitive_cube_add(size=1.0, location=loc, rotation=rot)
    ob = bpy.context.object
    ob.scale = Vector(tuple(
        size[axis] + 2 * (SKIN + _jitter.random() * JITTER) for axis in range(3)))
    return _finish(ob, swatch)
```

```python
# tools/model/checkmesh.py L610-L628
def unpaired_names(gltf):
    """Nodes whose mesh is not named after them, which KSA renders as nothing.

    Blender will not say when it refuses a name: `ob.data.name = "X"` silently becomes "X.001" if
    an orphaned mesh already holds "X", and deleting an object leaves exactly such an orphan. The
    export then writes a node "X" drawing a mesh "X.001", the asset XML's <Mesh Id="X"> resolves
    to nothing, and the part loads with that body missing and nothing in any log.
    """
    meshes = gltf.get("meshes", [])
    bad = []
    for node in gltf.get("nodes", []):
        index = node.get("mesh")
        if index is None or index >= len(meshes):
            continue
        node_name = node.get("name", "?")
        mesh_name = meshes[index].get("name", "?")
        if node_name != mesh_name:
            bad.append((node_name, mesh_name))
    return bad
```

## Pitfalls and version notes

- **Zero UV area is invisible in Blender.** Collapsing a face's loops onto one swatch centre gives
  a zero UV derivative and NaN tangents; the preview material has no normal map, so only the game
  shows the speckle. `project_to_swatch` keeps every face's patch non-degenerate.[^ksarmory-pantsir][^ksarmory-model-readme]
- **A uniform skin is not enough.** It separates faces pointing at each other, not faces pointing
  the same way on the same plane; that needs a different inflation per box. Cylinders bypass
  `box()` and need clearance by hand or a different facet count.[^ksarmory-model-readme]
- **The jitter has one seed.** Moving or adding a `box()` call reshuffles every box after it and
  can push two faces elsewhere onto one plane; change `_group` around the existing call instead.[^ksarmory-model-claude]
- **The atlas is not byte-reproducible.** Blender's exporter permutes the index buffer, so ask
  `checkmesh.py --compare` and revert an atlas whose geometry did not change.[^ksarmory-model-claude]
- **`checkmesh.py` sees one mesh at a time.** Planes shared between two bodies are found by
  `validate-parts.py`, which places bodies with the XML's `<Position>` and `<Rotation>`; a new
  articulated vehicle must be added to `checkswept.py`'s `vehicles()` or it is silently not swept.[^ksarmory-model-claude][^ksarmory-validate-parts]
- **Hand-built meshes skip what the add-primitive operators do**: selection before
  `transform_apply`, consistent outward winding, a single UV layer. A second `uv_layers.new()`
  leaves the wrong layer as `TEXCOORD_0`.[^ksarmory-model-readme]
- **`_VM` is not only an editor preview (observed in decomp).** The mod's export comment calls it
  the editor's preview variant; in build 5554 `Part.TryComputeOwnMeshExtentsAsmb` and
  `ComputeSubPartBoundingBox` accumulate bounds from `MeshViewModule.MeshView`, so a `_VM` mesh that
  differs from the rendered one changes the part's measured extents.[^ksa-part][^ksarmory-pantsir]
- **Environment-specific.** `build.sh` and the README assume Blender 5.2 as a Windows binary
  driven from WSL (`wslpath -w`, `C:\Windows\Temp` working folder); the checkers themselves are
  plain Python and run anywhere, including CI.[^ksarmory-model-build][^ksarmory-check-all]
