AFC's guidance contains thousands of lines of numerical code (UPFG, G-FOLD, SCvx, dual numbers, cone
assembly, native solver bindings) that does not need KSA to run. The project splits it into four
assemblies with no game references and tests them with console programs that compare against reference
outputs generated by Python, so the math is checked in CI on machines that have no game installed.

## How it works

### Project split

- `AdvancedFlightComputer.Guidance.Numerics`, `.Conic`, `.Gfold`, `.Scvx` are plain `net10.0` class
  libraries with no `KSA.dll` reference ([AdvancedFlightComputer/Features/Guidance/Numerics/AdvancedFlightComputer.Guidance.Numerics.csproj](https://github.com/Maximilian-Nesslauer/KSA-AdvancedFlightComputer/blob/77c0ccf5608e49c459eec72c3a56d0b30d62da63/AdvancedFlightComputer/Features/Guidance/Numerics/AdvancedFlightComputer.Guidance.Numerics.csproj)).
- The mod project excludes their source folders from its own compile items and references them as
  projects (`<Compile Remove="Features\Guidance\Numerics\**\*.cs;..."/>` plus four `ProjectReference`s),
  so the game-facing adapters live next to the solvers in the tree but compile separately
  ([AdvancedFlightComputer/AdvancedFlightComputer.csproj](https://github.com/Maximilian-Nesslauer/KSA-AdvancedFlightComputer/blob/77c0ccf5608e49c459eec72c3a56d0b30d62da63/AdvancedFlightComputer/AdvancedFlightComputer.csproj#L60-L66)).
- Only `Conic` calls native code, so the native libraries are copied beside it.

### Console checks

- `tests/AdvancedFlightComputer.Guidance.Tests/Scvx` is one executable with flags: `--fd` (forward-mode
  dual-number Jacobians against JAX's `jax.jacobian` from `python_ref/dyn_ref.py`), `--aero`, `--impact`,
  `--sub-scs` (one SCvx subproblem against CVXPY), `--loop` (the full SCvx loop against a reference), the
  ascent checks, `--cold-shift`, `--hermite` and more ([tests/AdvancedFlightComputer.Guidance.Tests/Scvx/Program.cs](https://github.com/Maximilian-Nesslauer/KSA-AdvancedFlightComputer/blob/77c0ccf5608e49c459eec72c3a56d0b30d62da63/tests/AdvancedFlightComputer.Guidance.Tests/Scvx/Program.cs)).
  The `python_ref` folder keeps the scripts and CSV fixtures (`dyn_ref.csv`, `sub_ref.csv`, `loop_ref.csv`).
- `tests/AdvancedFlightComputer.Guidance.Tests/Gfold` runs a reference descent (`81 120`), a Clarabel smoke
  test that also checks the CSC vertical stack against a dense reference, a real-time budget run, terminal
  braking and acceleration-limit checks, with a Python reference in `python_ref/gfold_ref.py`.
- `Worker.Tests` compiles the single game-facing file `Ksa6DofSolveWorker.cs` into a tiny executable with
  `<Compile Include="..." Link="..."/>` and checks its concurrency contract: concurrent dispatch has one
  winner, a disposed worker cannot return late results, a completed result waits for collection
  ([tests/AdvancedFlightComputer.Guidance.Tests/Worker.Tests/Worker.Tests.csproj](https://github.com/Maximilian-Nesslauer/KSA-AdvancedFlightComputer/blob/77c0ccf5608e49c459eec72c3a56d0b30d62da63/tests/AdvancedFlightComputer.Guidance.Tests/Worker.Tests/Worker.Tests.csproj),
  [tests/AdvancedFlightComputer.Guidance.Tests/Worker.Tests/Program.cs](https://github.com/Maximilian-Nesslauer/KSA-AdvancedFlightComputer/blob/77c0ccf5608e49c459eec72c3a56d0b30d62da63/tests/AdvancedFlightComputer.Guidance.Tests/Worker.Tests/Program.cs)).
- `build/ci/test-guidance.ps1` builds the natives, builds the eight game-free projects (locked restore,
  then `--no-restore --runtime <rid>`), runs the ABI check, then every Gfold and Scvx flag and
  `Worker.Tests`, stopping on the first failure ([build/ci/test-guidance.ps1](https://github.com/Maximilian-Nesslauer/KSA-AdvancedFlightComputer/blob/77c0ccf5608e49c459eec72c3a56d0b30d62da63/build/ci/test-guidance.ps1)). The CI native jobs run it
  on Windows and Linux.

## Lifecycle and timing

Not part of the game frame: these run at build and CI time as ordinary .NET console programs. The design
consequence for the mod is that solver code may not read game state; the adapters copy everything into
plain data before a solve, which is also what makes background solve threads safe (see
[6-DOF SCvx landing MPC](scvx-6dof-landing-mpc.md)).

## Game APIs touched

None, by design.

## Pitfalls and version notes

- Keep game-free assemblies free of `KSA.dll` references; a single `using KSA;` in a solver file breaks the
  CI jobs that have no game.
- Reference fixtures pin behavior; when an algorithm changes on purpose, regenerate the Python outputs
  with the scripts kept in `python_ref`.
- The `--fd`, `--aero` and `--impact` checks need no native solver; the others do.
