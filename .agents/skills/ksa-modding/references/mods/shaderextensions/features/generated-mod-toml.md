The repository contains no `mod.toml`. The build writes one into the output folder from MSBuild
properties and items, so the version, the entry assembly and the StarMap dependency on KittenExtensions
Continued live in the project file next to the references they mirror.[^sx-copyoutput] [^sx-csproj]

## How it works

1. **Copy step.** `CopyBuildOutput` runs `AfterTargets="Build"` and calls `_CopyToSingleDestination`
   once per `CopyDestination` item (here only `../Release/$(ModName)/`). It deletes and recreates the
   folder and copies everything under `$(OutputPath)` preserving sub-folders
   ([ShaderExtensions/CopyOutput.targets](https://github.com/AMPW-german/ShaderExtensions/blob/6a2eb66ea85bcaa2d4657e502a4f75e92693ea77/ShaderExtensions/CopyOutput.targets#L1-L43)).
2. **Manifest lines.** It writes `name`, `version = "v$(Version)"`, `author = "$(Authors)"`,
   `description = "$(Description)"`, one `key = [ ... ]` array line per distinct `ModManifestArray`
   metadata value found on `None` items (none in this project, so no `assets` line), then `[StarMap]`
   with `EntryAssembly = "$(AssemblyName)"`
   ([ShaderExtensions/CopyOutput.targets](https://github.com/AMPW-german/ShaderExtensions/blob/6a2eb66ea85bcaa2d4657e502a4f75e92693ea77/ShaderExtensions/CopyOutput.targets#L45-L75)).
3. **Dependency block.** For each `StarMapModDependency` item it emits `[[StarMap.ModDependencies]]`,
   `ModId`, `Optional` (metadata, default `false`, lower-cased) and `ImportedAssemblies` built from the
   semicolon list in metadata
   ([ShaderExtensions/CopyOutput.targets](https://github.com/AMPW-german/ShaderExtensions/blob/6a2eb66ea85bcaa2d4657e502a4f75e92693ea77/ShaderExtensions/CopyOutput.targets#L77-L97)). The csproj
   declares one: `KittenExtensionsContinued` importing the `KittenExtensions` assembly
   ([ShaderExtensions/ShaderExtensions.csproj](https://github.com/AMPW-german/ShaderExtensions/blob/6a2eb66ea85bcaa2d4657e502a4f75e92693ea77/ShaderExtensions/ShaderExtensions.csproj#L68-L72)).
4. **What StarMap does with it.** `ModDependencies` and `ImportedAssemblies` map onto StarMap's
   `StarMapConfig`; a mod whose required dependency is not loaded yet is put on a waiting list and
   initialized after it, and `ImportedAssemblies` limits which of the dependency's assemblies become
   visible to the dependent's load context
   ([StarMap.Core/Config/StarMapConfig.cs](https://github.com/StarMapLoader/StarMap/blob/4dc60f8dfeb1d9b035d44af2601d09115c16d2aa/StarMap.Core/Config/StarMapConfig.cs#L17-L24),
   [StarMap.Core/ModRepository/RuntimeMod.cs](https://github.com/StarMapLoader/StarMap/blob/4dc60f8dfeb1d9b035d44af2601d09115c16d2aa/StarMap.Core/ModRepository/RuntimeMod.cs#L78-L127)).[^sm-config] [^sm-runtimemod]
5. **Versioning.** `VersionPrefix` 1.0.5 drives `Version` and the manifest version;
   `SetVersionMetadata` runs `git rev-parse --short HEAD` before `GetAssemblyVersion` and sets
   `InformationalVersion` to `v1.0.5.<hash>` with `-debug` appended in Debug builds
   ([ShaderExtensions/ShaderExtensions.csproj](https://github.com/AMPW-german/ShaderExtensions/blob/6a2eb66ea85bcaa2d4657e502a4f75e92693ea77/ShaderExtensions/ShaderExtensions.csproj#L21-L28),
   [ShaderExtensions/ShaderExtensions.csproj](https://github.com/AMPW-german/ShaderExtensions/blob/6a2eb66ea85bcaa2d4657e502a4f75e92693ea77/ShaderExtensions/ShaderExtensions.csproj#L74-L85)).

Resulting manifest keys for this project:

| Key | Value |
|---|---|
| `name` | `ShaderExtensions` (the manifest id players put in `manifest.toml`) |
| `version` | `v1.0.5` |
| `author` | `AMPW` |
| `description` | empty (`$(Description)` is not set) |
| `[StarMap] EntryAssembly` | `ShaderExtensions` |
| `[[StarMap.ModDependencies]]` | `ModId = "KittenExtensionsContinued"`, `Optional = false`, `ImportedAssemblies = [ "KittenExtensions" ]` |

## Lifecycle and timing

Build time only. At runtime the manifest decides load order: StarMap initializes KittenExtensions
Continued before ShaderExtensions, which is what puts KittenExtensions' `Program.Main` prefix ahead of
ShaderExtensions' (see [Custom XML asset types](xml-asset-types-and-element-injection.md)).

## Game APIs touched

None; this is build tooling. The game assemblies are referenced with `Private=False` through
wildcards over `$(KSADir)` (`Brutal*.dll`, `KSA.dll`, `Planet*.dll`, `Tomlet.dll`)
([ShaderExtensions/KSADLLs.props](https://github.com/AMPW-german/ShaderExtensions/blob/6a2eb66ea85bcaa2d4657e502a4f75e92693ea77/ShaderExtensions/KSADLLs.props#L1-L13)).[^sx-ksadlls]

## Pitfalls and version notes

- **`KSADir` and `KSAModsDir` have no defaults** in the repository; local builds must pass them
  (`/p:KSADir=... /p:KSAModsDir=...`) as the CI does. `StarMap.API.dll` and `KittenExtensions.dll`
  are resolved from `$(KSAModsDir)StarMap/` and `$(KSAModsDir)KittenExtensionsContinued/`.
- **`ShaderExtensions.props` is not imported.** It duplicates `KSADLLs.props` plus a Harmony reference;
  the csproj imports only `KSADLLs.props` and `CopyOutput.targets`.[^sx-props]
- **The output folder is wiped** on every build (`RemoveDir`), so nothing else should live in
  `Release/ShaderExtensions/`.
- **KittenExtensions Continued, not KittenExtensions.** The dependency id is
  `KittenExtensionsContinued`, while the assembly keeps the name `KittenExtensions`; the README warns
  that the original KittenExtensions and KXC cannot be installed together.[^sx-readme]
- **Debug profile.** `launchSettings.json` starts `StarMap.exe` from the author's mods folder, a
  machine-specific path to adjust locally.[^sx-launch]
