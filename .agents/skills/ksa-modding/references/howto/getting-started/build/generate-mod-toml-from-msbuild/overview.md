A hand-written `mod.toml` is a second copy of facts the project already knows: the assembly name, the version, the asset
files, the dependencies and their imported assemblies. Generating it removes the drift. Three AMPW mods (KittenExtensions,
ShaderExtensions, MPFX) ship no `mod.toml` in git; a shared `CopyOutput.targets` writes it into `Release/<ModName>/` and
optionally the mods folder on every build.

## Engine background

| Reader | What it needs from the file | Source |
|---|---|---|
| KSA | `name` and the content keys (`assets`, `systems`, `fonts`, ...) as `[TomlField]` members of `Mod`; `Id` comes from the folder name | [current/decomp/KSA/Mod.cs](https://github.com/meow-sci/ksa-game-assemblies/blob/935a32b4dbc34cbcd16e87d16cf9732eb90030c0/current/decomp/KSA/Mod.cs#L26-L89) |
| StarMap | `[StarMap] EntryAssembly` and `[[StarMap.ModDependencies]]` (`ModId`, `Optional`, `ImportedAssemblies`) | [StarMap.Core/Config/StarMapConfig.cs](https://github.com/StarMapLoader/StarMap/blob/4dc60f8dfeb1d9b035d44af2601d09115c16d2aa/StarMap.Core/Config/StarMapConfig.cs#L7-L25) |

Unknown keys (`version`, `author`, `description`) are ignored by both. Build time only; the output is read at
`startup:starmap-before-main` and `startup:asset-load` ([Game loop and mod lifecycle](../../lifecycle/game-loop-and-lifecycle/overview.md)).

## Approaches

| Article | Mod | Technique | Lifecycle | Trade-off |
|---|---|---|---|---|
| [Shared CopyOutput.targets writing mod.toml](./generate-mod-toml-from-msbuild.md) | KittenExtensions, ShaderExtensions, MPFX | `msbuild`, `toml-config` | build | Manifest cannot drift and dependencies are declared next to the references they mirror; the manifest is not in git, only scalar and array keys and dependencies are supported, and each build wipes the destination folder |
