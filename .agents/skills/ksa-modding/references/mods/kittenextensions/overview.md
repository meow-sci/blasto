KittenExtensions Continued (KXC) is a KSA modding utility maintained by AMPW as a continuation of
tom_is_unlucky's KittenExtensions; the README gives the original author all the credit and the csproj
lists both as authors.[^kx-readme] [^kx-csproj] It does two things for other mods:

- **XML patching.** Any mod can ship XPath-based patch files that change any XML file of Core or of
  another mod. The patches run once at startup over a single in-memory document assembled from every
  installed mod's data files, and the game then reads its data from the patched document.
- **New XML asset types.** A code mod can tag a class with a `KxAsset` or `KxAssetInject` attribute and
  every mod's asset XML can then use it as a new element.

It ships no content and no gameplay. It is infrastructure: ShaderExtensions and MPFX require it as a
non-optional StarMap dependency, KSA_AircraftHUD uses elements it registers on ShaderExtensions'
behalf, and KSA-AdvancedFlightComputer ships patch files for it. Shader features moved to the separate
ShaderExtensions mod ([README.md](https://github.com/AMPW-german/KittenExtensions/blob/b52467541a4fda3c3771eb2c157ed7574f9e2d7c/README.md#L11)).

## Loader model and entry class

StarMap mod. The entry class is `KittenExtensions.KxMod`, marked `[StarMapMod]`
([KittenExtensions/Mod.cs](https://github.com/AMPW-german/KittenExtensions/blob/b52467541a4fda3c3771eb2c157ed7574f9e2d7c/KittenExtensions/Mod.cs#L8-L22)).[^kx-mod] It uses one StarMap attribute; everything else is
Harmony patches it installs from there ([KittenExtensions/Patches.cs](https://github.com/AMPW-german/KittenExtensions/blob/b52467541a4fda3c3771eb2c157ed7574f9e2d7c/KittenExtensions/Patches.cs#L10-L80)).[^kx-patches]

| Hook | Kind | Fires | What KXC does |
|---|---|---|---|
| `KxMod.Setup` | `[StarMapBeforeMain]` | While StarMap loads mods, before the game's entry point ([StarMap.Core/ModRepository/RuntimeMod.cs](https://github.com/StarMapLoader/StarMap/blob/4dc60f8dfeb1d9b035d44af2601d09115c16d2aa/StarMap.Core/ModRepository/RuntimeMod.cs#L156-L159)) | Deletes the previous `KittenExtensions.log`; `new Harmony("KittenExtensions").PatchAll()` |
| `Program.Main` | Harmony prefix | When StarMap invokes the game entry point, after every mod assembly is loaded ([StarMap/GameSurveyer.cs](https://github.com/StarMapLoader/StarMap/blob/4dc60f8dfeb1d9b035d44af2601d09115c16d2aa/StarMap/GameSurveyer.cs#L47-L55)) | `AssetEx.Init`: discover `KxAsset` attributes in all load contexts, extend `XmlHelper.AttributeOverrides`, rebuild serializers |
| `ModLibrary.PrepareAll` | Harmony prefix | `Program` constructor, before the per-mod loop ([current/decomp/KSA/Program.cs](https://github.com/meow-sci/ksa-game-assemblies/blob/935a32b4dbc34cbcd16e87d16cf9732eb90030c0/current/decomp/KSA/Program.cs#L899)) | Build the GameData document, run all patches (or the debug stepper), write the log |

KXC does not use `StarMapImmediateLoad`, `StarMapAllModsLoaded` or any frame hook.[^starmap-runtimemod] [^starmap-gamesurveyer]

`StarMapAllModsLoaded` therefore sees deserialized, patched templates (except editor tag definitions
and random heightmap collections) whose game data has not yet been merged by `AttachGameData`.

XML files in `StarMapImmediateLoad` (step 6) or later is not seen by the redirected loaders, which
read the copy imported in step 5.[^ksa-program] [^ksa-modlibrary] [^ksa-mod] [^ksa-modmanifest] [^starmap-starmapcore] [^starmap-modloader] [^starmap-program] [^starmap-modlibrarypatches] [^starmap-modpatches]

Everything runs on the main thread during startup; KXC owns no threads and does nothing after
`LoadAll`. Data flow: every manifest mod's `mod.toml` lists XML files, which are imported into one
XPathPatch document; the executor applies every `<Patch>` (execution semantics come from the README,
because the XPathPatch source is not in the checkout); the transpiled `Mod` loaders read file
nodes back through an `XmlReader` over that document with serializers that know the custom element
types; the resulting objects go through the game's normal `OnDataLoad` and registration.

## Build, test and tooling

- .NET 10 (`net10.0`), C# 14, nullable enabled, unsafe allowed; output to `bin/<Configuration>` without
  a framework subfolder ([KittenExtensions/KittenExtensions.csproj](https://github.com/AMPW-german/KittenExtensions/blob/b52467541a4fda3c3771eb2c157ed7574f9e2d7c/KittenExtensions/KittenExtensions.csproj#L3-L23)).
- `dotnet build` needs `KSADir` (game install) and `KSAModsDir` (mods folder, for StarMap.API); the
  checked-in `.csproj.user` sets both for the author's machine and adds the mods folder as a deploy
  target. Each build regenerates `mod.toml` and replaces `Release/KittenExtensionsContinued/` and the
  installed copy (see [MSBuild-generated mod.toml and deploy](features/msbuild-mod-toml-generation.md)).
- Clone with `--recursive`: the XPathPatch project is a submodule.
- CI ([.github/workflows/build.yml](https://github.com/AMPW-german/KittenExtensions/blob/b52467541a4fda3c3771eb2c157ed7574f9e2d7c/.github/workflows/build.yml)) builds against a private KSA DLL repository and, when
  `VersionPrefix` changes on `main`, publishes a GitHub release and a SpaceDock update.[^kx-build-yml]
- There are no automated tests in this repository; the [patch debug stepper](features/patch-debug-stepper.md)
  and the [patch session log](features/patch-session-log.md) are the diagnostic tools.

## Compatibility

- The README names no KSA build. CI stamps each release body with the KSA version read from the
  private DLL repository ([.github/workflows/build.yml](https://github.com/AMPW-german/KittenExtensions/blob/b52467541a4fda3c3771eb2c157ed7574f9e2d7c/.github/workflows/build.yml#L207-L216)). Version `0.5.2` at this ref.
- Checked against decompiled build 2026.10.10.5554: all four transpiled `Mod` methods exist and call
  `XmlLoader.Load<T>` ([current/decomp/KSA/Mod.cs](https://github.com/meow-sci/ksa-game-assemblies/blob/935a32b4dbc34cbcd16e87d16cf9732eb90030c0/current/decomp/KSA/Mod.cs)); `XmlHelper.Serializers`,
  `XmlHelper.AttributeOverrides` and the save serializers' backing fields match the names KXC
  uses.[^ksa-mod]
- Gaps in this build: `Mod.LoadEditorTagDefinitions` and `Mod.LoadPlanetRandomHeightmaps` also call
  `XmlLoader.Load<T>` and are not redirected, and `planetRandomHeightmapCollections` files are not
  imported, so patches cannot reach them ([current/decomp/KSA/Mod.cs](https://github.com/meow-sci/ksa-game-assemblies/blob/935a32b4dbc34cbcd16e87d16cf9732eb90030c0/current/decomp/KSA/Mod.cs#L171-L190),
  [current/decomp/KSA/Mod.cs](https://github.com/meow-sci/ksa-game-assemblies/blob/935a32b4dbc34cbcd16e87d16cf9732eb90030c0/current/decomp/KSA/Mod.cs#L364-L387)).
  For editor tags the effect is stronger than "not patched": `PreloadAssetBundles` never calls
  `EditorTagDefinition.OnDataLoad`, so the unpatched `LoadEditorTags` pass is the first to register
  every `<EditorTagDef>` ([current/decomp/KSA/EditorTagDefinition.cs](https://github.com/meow-sci/ksa-game-assemblies/blob/935a32b4dbc34cbcd16e87d16cf9732eb90030c0/current/decomp/KSA/EditorTagDefinition.cs#L25-L33)), and
  `SerializedCollection.Register` keeps the first entry per id
  ([current/decomp/KSA/SerializedCollection.cs](https://github.com/meow-sci/ksa-game-assemblies/blob/935a32b4dbc34cbcd16e87d16cf9732eb90030c0/current/decomp/KSA/SerializedCollection.cs#L20-L35)). The patched copies that
  `LoadAll` deserializes later are rejected, and a tag a patch adds registers after
  `VehicleEditor.MarkEditorTagDefinitionsLoaded` has read the flags. Patches to `<EditorTagDef>`
  therefore do not change editor behaviour in this build.[^ksa-editortagdefinition] [^ksa-serializedcollection]
- The README's examples predate current data and types: its Venus patch path does not match Core's
  `SolSystem.xml`, it uses a `<Remove>` element that the README's own operation reference does not
  document and that has no `Op*` action type in KXC's logger (whether XPathPatch accepts it cannot be
  checked, because the submodule is not in the checkout), and its C# samples reference
  `GaugeBoxReference.Color` and `ColorReference`, which do not exist in this build (details in
  [XML patch files](features/xpath-patch-operations.md) and
  [Custom XML asset types](features/custom-xml-asset-types.md)).
- Stricter failure mode than stock: an unparsable `mod.toml`, or any exception while XPathPatch
  imports a listed XML file (a malformed file is the expected trigger; the import code is in the
  submodule), in any installed mod, enabled or not, ends startup with KXC's error dialog, where the
  stock `XmlLoader` would log and continue
  ([current/decomp/KSA/XmlLoader.cs](https://github.com/meow-sci/ksa-game-assemblies/blob/935a32b4dbc34cbcd16e87d16cf9732eb90030c0/current/decomp/KSA/XmlLoader.cs#L20-L33)).[^ksa-xmlloader]
- Breakage to expect: renamed or new `Mod` loader methods, a renamed `XmlLoader.Load`, changes to
  `XmlHelper`, renamed `GameSaves.UniverseSerializer` / `VehicleSaves.VehicleSerializer` properties
  (bound by backing-field name through `UnsafeAccessor`), and changes to `SelectSystem`'s startup frame
  loop, which `PopupTask` copies.
- The patch format "is not finalized and may change" ([README.md](https://github.com/AMPW-german/KittenExtensions/blob/b52467541a4fda3c3771eb2c157ed7574f9e2d7c/README.md#L33-L34)).
