# Game Feature

* [Drive the flight computer and attitude modes from a mod](overview.md) - Write a Custom attitude target so the stock controller flies a mod-computed attitude, command gimbals, and pick the write window that is not erased, raced or seen a step late

# How-To

* [Command other vehicles through queued writes performed in a PrepareWorker prefix](drive-the-flight-computer-and-attitude-modes-from-a-mod-2.md) - Queue attitude, pulse mode, staging and quiet commands per vehicle from the frame hooks and replay them in one Vehicle.PrepareWorker prefix, the moment before KSA snapshots the flight computer
* [Custom attitude in an inertial frame plus turning-rate feedforward, gimbal commands and thrust inversion](drive-the-flight-computer-and-attitude-modes-from-a-mod-4.md) - Command an inertial Custom attitude from the PrepareWorker prefix, add the target's own turning rate with a postfix on the private UpdateAttitudeTarget, write gimbal demands after ComputeControl, and turn a thrust demand into a throttle
* [Edit ComputeControl inputs by ref in a prefix and restore them in a finalizer](drive-the-flight-computer-and-attitude-modes-from-a-mod-7.md) - Change the by-ref navigation struct the vehicle worker passes to ComputeControl for exactly one call, and put it back afterwards, so the stock controller sees a value the game did not build
* [Orient a vehicle to a sky direction from a Vehicle.PrepareWorker prefix](drive-the-flight-computer-and-attitude-modes-from-a-mod-1.md) - Point the nose at a star by writing Auto, the EclBody frame and a Custom attitude target with solved Euler angles every physics dispatch, and restore the previous mode and rate command on exit
* [Patch every attitude-mode writer so the player can take back control](drive-the-flight-computer-and-attitude-modes-from-a-mod-9.md) - Release your Custom target whenever any stock path changes the attitude mode (SetEnum, ToggleEnum, SetStabilization, TrackTarget, RateHold, SetNullRot, kitten actions) and when the kitten MMU takes over, without breaking the game method
* [Queue vehicle changes in your own ConcurrentQueue and drain it in an ApplyInputEvents prefix](drive-the-flight-computer-and-attitude-modes-from-a-mod-8.md) - Let the UI only enqueue requests and apply them from a prefix on InputEvents.ApplyInputEvents, at the stock input point, before the stock buffers are consumed and before the next snapshot
* [Run a main-thread tick around Universe.ApplyVehicleSolvers](drive-the-flight-computer-and-attitude-modes-from-a-mod-6.md) - Use a prefix and postfix on the static ApplyVehicleSolvers to sample before the apply and act on fresh physics results afterwards, before input is drained and before stock reacts to burn flags
* [Set attitude mode and an arbitrary quaternion from a solver-phase command drain](drive-the-flight-computer-and-attitude-modes-from-a-mod-3.md) - Drain a second command queue in a Priority.First prefix on Universe.ExecuteNextVehicleSolvers, convert a requested body-to-CCI quaternion to EclBody Euler angles for the Custom track, and understand why frame-phase writes are erased by CopyFrom
* [Write actuator commands from one worker-thread postfix on FlightComputer.ComputeControl](drive-the-flight-computer-and-attitude-modes-from-a-mod-5.md) - Own exactly one postfix on ComputeControl that runs every actuator writer in a fixed order on the vehicle worker, with immutable commands and a merged receipt for the physics step
